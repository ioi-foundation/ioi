# Streaming recovery — final scoped revision

All recorded checks pass with unchanged selected source hashes: 64 QUV tests, 21 runtime tests, CLI test-target compilation, formatting and runner syntax. The existing durability benchmark remains ignored in the core suite and was not rerun. `started.json`, `sources/`, `results.json`, `completed.json` and `environment.json` retain exact source subsets, commands, logs and tool versions. This is not a clean full M16Q campaign or immutable R2 candidate.

Reopen no longer stores every record path and transition payload in memory. It validates canonical unique names, record count and maximum generation, authenticates the entire contiguous chain, then rereads and reauthenticates individual records into private semantic replay. Both passes verify the anchored prefix; the second must end at the first pass's exact head before a pending anchor advances. The format and all existing records remain unchanged by this streaming revision.

Fourteen journal tests cover ordinary ordered replay, pending recovery and its refusal, bootstrap interruption, storage limits, exclusive opening, temporary-record cleanup, final continuation refusal, write quarantine and the new streaming checks. The new cases reject missing/noncanonical indices before replay and changes to the pending tail between passes, including a locally reauthenticated replacement. Failed recovery leaves the anchor unchanged; restoring the original tail permits exact recovery.

The improvement bounds auxiliary path/payload buffering independently of retained record count. It does not bound reconstructed member state independently of retained contents, allocated filesystem bytes, or worst-case recovery latency. Recovery now reads and authenticates records twice. Rooted finite lifetime, byte/rate/slot quotas, safe retention/compaction, aggregate service and recovery qualification, full refinement, clean R2 and fresh independent review remain required. All whole R1 findings remain open; M18Q is unadmitted.
