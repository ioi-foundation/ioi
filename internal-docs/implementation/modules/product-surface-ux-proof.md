# Product-Surface And UX Proof Method

The master activates this method only inside M6/WP-UX. Canon owns application
identity and route/object meaning. The generated Hypervisor coverage projection
owns the current census; this module never freezes a route, seed, or application
count.

## Classification and source convergence

Every reachable item is classified as one of: core workspace, owner
application, substrate application, conditional application, tool/support
surface, generated/installed application, compatibility alias, reference
capture, dormant evidence, or retirement target. One normalized compiler must
join the exact `HypervisorApplicationSurfaceRegistration`, release,
installation, System-interface, serving, route-alias, and request-scoped
projection families.

Reference capture, route reachability, HTTP 200, registration, pixel parity,
and a screenshot are evidence inputs only. None grants product membership,
operational depth, owner truth, or authority. The adopted ported app estate is
nevertheless the executable migration seed: source ownership is achieved by
rebinding or extracting that exact implementation, not by observing it and
creating a parallel shell. Convergence must be app by app without losing deep
links, query/hash/embed/return-path, Project, System, typed subject context,
focus, narrow-layout behavior, or accessibility.

contract, positive/denial/fault/recovery proof, parity proof, and negative
no-fallback proof are all present. The shared bundle/serve boundary retires
only when this census has zero unresolved live seeds.

QM is an implementation starting point, not an architecture owner, truth store,

to Workflow Compositor templates rather than owned by them.

## Required state proof

For each admitted workspace/application and consequential control, retain a
matrix for:

- loading, honest empty, populated, and completed;
- denied, expired, revoked, wrong-tenant, and wrong-System;
- unavailable, degraded, stale/conflict, retry, ambiguous effect, recovery,
  and terminal failure;
- in-flight, cancellation, restart, reconciliation, and receipt verification;
- modal/drawer/panel/embed context and focus return; and
- desktop and representative narrow widths, keyboard traversal, accessible
  name/status, reduced motion, touch targets, and wide table/graph overflow.

Fixture data must be confined to an explicit reference profile. Loss of daemon
truth must render a typed unavailable/degraded state and may never fall back to
plausible production data.

## Consequential-action proof

Every action maps to one owner contract, policy decision, applicable wallet
grant or sealed intent, daemon-side revalidation, final invoker, idempotency
key, accepted-truth operation, and effect receipt. A control being enabled is
not authority. Denial, substitution, stale head, expiry, revocation, retry, and
missing receipt must fail closed before the invoker or remain explicitly
ambiguous with a reconciliation obligation.

## Outputs and nonclaims

The method produces the generated surface census, current-source disposition,
owner/app journey map, state/accessibility matrix, consequential-action map,
fixture-retirement ledger, and focused browser/adversarial evidence. M6 proves
registration, routing, honest shell states, and the eight master-assigned M6
journeys. Later owner records prove later operational depth. It proves no
multi-node, federation, live-embodied, connected-service, or L1 behavior.
