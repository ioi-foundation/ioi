## Meaning Stays Local First

Before two institutions can exchange work they must exchange *meaning*, and
IOI refuses the tempting shortcut of one shared database of meaning.

There is no universal enterprise graph. Each domain owns local ontology
versions, overlays, assertions, valid time, transaction time, provenance,
uncertainty, contradictions, supersession, and disputes. Cross-domain work,
when selected under accepted terms, uses explicit `OntologyCrosswalk` and
`SemanticMappingDecision` objects.

Semantic meaning never grants power. A consequential ontology action becomes
executable only through an `OntologyActionContract` binding typed IO,
preconditions, postconditions, state transition, capability, runtime, policy,
authority, risk, idempotency, ambiguous-effect recovery, compensation,
verification, evidence, receipts, and physical safety where applicable. Owner:
[`domain-ontologies-and-data-recipes.md`](../foundations/domain-ontologies-and-data-recipes.md).

## Where AIIP Begins

[`aiip.md`](../foundations/aiip.md) owns the boundary exactly: AIIP begins only
where a separate constitution, operational truth, authority, risk, and
credible exit create an independently governed system boundary. Transport
never decides the layer — the same socket carries L0 inside one system and
AIIP across two. A worker, process, node, or installed package under the
caller's `system_id` is never an AIIP peer merely because it has its own
runtime.

AIIP is RPC-shaped and receipt-native: typed packets for discovery, task
offers and acceptance, collaboration-terms proposal and response, handoffs,
semantic-profile negotiation, room participation, attempts and findings,
verifier challenges, authority queries, receipt commitments, deliveries,
acceptance, settlement intents, disputes, and reputation queries. It composes
with existing standards — A2A for remote tasks, MCP for tools and context,
directory and EVM bindings — through versioned binding envelopes that reuse
each standard for the boundary it owns without letting its completion state
become IOI verification or authority.

The decisive rule is the **conditional cooperation thesis**: AIIP creates an
option to interoperate, never a duty. A sovereign system is complete locally;
it participates only when its expected utility under one exactly accepted
`CollaborationTermsEnvelope` root exceeds its best permitted outside option
plus every incremental cooperation cost — and that valuation may stay private.
Discovery, compatibility, invitations, offers, and terms proposals create no
obligation, authority, award, or payout; terms acceptance, work claim,
contribution, verification, acceptance, and settlement remain distinct stages.
The assurance ladder from chapter 02 crosses domains intact: a receipt is an
authenticated boundary statement, and verification, acceptance, adjudication,
and settlement remain later, distinct states.

Hugging Face-style open-agent experiments demonstrate one high-fit pattern for
goals where parallel attempts, negative results, independent challenges, and
shared resources create positive expected value. IOI supports that pattern
alongside direct local work, private rooms, bilateral handoffs, enterprise
workflows, and embodied systems; it does not presume open participation. A
sovereign system remains local unless accepted terms make every required
party's participation rational after coordination, disclosure, verification,
and counterparty costs.

## Enrollment Is Explicit; Settlement Is Sparse

IOI Network participation is a versioned choice, never an ambient dependency.
The three profiles are owned by
[`governed-autonomous-systems.md`](../foundations/governed-autonomous-systems.md)
and [`ioi-l1-mainnet.md`](../foundations/ioi-l1-mainnet.md): `ioi_compatible`
uses open L0 with no mandatory L1, fee, or token; `ioi_connected` pays only
for selected registry, rights, reputation, escrow, dispute, or settlement
services; `ioi_secured` additionally adopts a Standard DAS profile and named
bonded shared-security services. Connection is not security, and compatibility
is not endorsement.

IOI L1 itself is the optional neutral public-trust utility: registries,
rights, escrows, bonds, disputes, reputation roots, handoff finality, and
governance for explicitly enrolled systems. It does not run application state,
execute workflows, or receive every receipt. Its own gas boundary states the
division this whole guide has been building toward:

> **The chain prices commitments. The runtime prices work.**

## The Test That Names The Network

When has any of this added up to an Internet of Intelligence? The north-star
network proof is stated once, in full, by
[`internet-of-intelligence.md`](../foundations/internet-of-intelligence.md)
§ North-Star Network Proof — an independently operated external Worker
completing the whole arc without sharing a runtime, an operational database,
an administrator, or continued access to an IOI-hosted room. This paragraph is
navigation; the owner wins on any point of substance, and same-owner
multiplicity never satisfies it.
