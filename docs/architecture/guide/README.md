## What This Is

This guide is the deliberately authored book in front of the canonical owner
corpus. It tells the architecture as one progressive story — one beginning,
one causal spine, one zoom from a single consequential action out to a network
economy of sovereign institutions — so that a reader can first understand the
system and then verify it against the owner documents underneath.

Its contract is strict and simple:

- **It owns nothing but sequence.** Every load-bearing statement links to the
  canonical owner that states it authoritatively. Where this guide and an owner
  disagree, the owner is right and this guide has a defect.
- **It originates no doctrine.** Deleting this directory would lose reading
  order and synthesis — never a fact, a rule, or a boundary.
- **It makes no implementation claims.** What is built, partial, or planned is
  recorded by [`canon-to-code-delta.md`](../_meta/canon-to-code-delta.md) and
  the [`work-items/`](../_meta/work-items/) records; chapter 08 is a map to
  those indexes, not a status report.

## The Chapters

Read them in order; each assumes only its predecessors.

1. [`00-why-ioi.md`](./00-why-ioi.md) — the problem: intelligence can reason
   anywhere, but consequential power cannot be ambient. Why an effect boundary,
   authority, evidence, operational truth, and sovereign interop must exist.
2. [`01-the-system-in-one-page.md`](./01-the-system-in-one-page.md) — the
   strata, stated once: products, applications within products, clients, and
   the substrates and protocols beneath them.
3. [`02-from-intent-to-effect.md`](./02-from-intent-to-effect.md) — one action
   end to end on a local deployment: the causal spine everything else hangs on.
4. [`03-the-bounded-das.md`](./03-the-bounded-das.md) — from a run to an
   institution: GoalRun, OutcomeRoom, and the bounded distributed autonomous
   system.
5. [`04-one-institution-across-nodes.md`](./04-one-institution-across-nodes.md)
   — one `system_id` across admitted nodes, and why multi-node never means
   multi-party.
6. [`05-sovereign-interop-and-settlement.md`](./05-sovereign-interop-and-settlement.md)
   — where AIIP begins, what enrollment means, and what IOI L1 is actually for.
7. [`06-products-over-the-architecture.md`](./06-products-over-the-architecture.md)
   — the products mapped onto the machinery the previous chapters explained.
8. [`07-learning-improvement-and-recovery.md`](./07-learning-improvement-and-recovery.md)
   — how an institution learns, improves, and recovers without escalating
   itself.
9. [`08-current-state.md`](./08-current-state.md) — where implementation truth
   lives and how to read a status claim.
